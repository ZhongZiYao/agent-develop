## 2. 模块详细设计

### 2.1 Loader 层（src/loaders/）

```python
# src/loaders/base.py
class BaseLoader(ABC):
    def load(self, path: str) -> List[Document]: ...

# 实现
- MarkdownLoader   # 处理 .md，按标题分块
- HTMLLoader       # 用 BeautifulSoup 清洗
- PDFLoader        # 用 pypdf / PyMuPDF
- JSONLoader       # 处理 API dump
```

**接口约定**：
- 输入：文件路径 / URL / 目录
- 输出：`List[Document]`（每个含 `page_content` + `metadata`）
- metadata 包含：`source`、`url`、`title`、`timestamp`、`game`

### 2.2 Splitter 层（src/splitters/）

```python
# src/splitters/base.py
class BaseSplitter(ABC):
    def split(self, docs: List[Document]) -> List[Chunk]: ...
```

**策略**：
| Splitter | 适用 | 参数 |
|----------|------|------|
| RecursiveCharSplitter | 通用 | chunk_size=500, overlap=50 |
| MarkdownHeaderSplitter | Markdown | 按 H1/H2/H3 分 |
| SemanticSplitter | 长文 | embedding 相似度 < 阈值就断 |
| CodeSplitter | 代码块 | 按函数/类 |

**经验值**：
- 中文游戏攻略：500-800 token / chunk，overlap 50-100
- 装备/技能描述：完整一块，不切

### 2.5 Retriever 层（src/retrievers/）

**两阶段召回**：

```python
# src/retrievers/hybrid.py
class HybridRetriever:
    def __init__(self, vector_store, bm25_index, weight=0.5):
        self.vector_store = vector_store
        self.bm25_index = bm25_index
        self.weight = weight  # 向量权重
    
    def retrieve(self, query: str, top_k: int = 50) -> List[Chunk]:
        # 1. 向量召回 top_k
        vec_results = self.vector_store.search(query, top_k)
        # 2. BM25 召回 top_k
        bm25_results = self.bm25_index.search(query, top_k)
        # 3. RRF 融合
        return rrf_fusion(vec_results, bm25_results, weight=self.weight)
```

**RRF（Reciprocal Rank Fusion）公式**：
```
score(d) = Σ weight_i / (k + rank_i(d))
```
- k 常取 60
- 默认 weight = 0.5（向量）/ 0.5（BM25）

### 2.8 Agent 层（src/agents/）—— Phase 4

**LangGraph 多 Agent 架构**：

```python
# src/agents/state.py
class AgentState(TypedDict):
    query: str
    plan: List[str]                # Planner 拆解的子问题
    sub_results: List[SubResult]   # Researcher 的检索结果
    draft: str                     # Writer 的草稿
    critique: Optional[str]        # Critic 的反馈
    final_answer: str
    iteration: int                 # 反思次数

# src/agents/graph.py
workflow = StateGraph(AgentState)
workflow.add_node("planner", planner_node)
workflow.add_node("researcher", researcher_node)
workflow.add_node("writer", writer_node)
workflow.add_node("critic", critic_node)
workflow.add_edge("planner", "researcher")
workflow.add_conditional_edges(
    "critic",
    lambda s: "researcher" if s["iteration"] < 3 and needs_retry(s) else END
)
```

## 3. 数据流

### 3.1 离线索引流程（一次）

```
raw docs (Wiki/PDF/HTML)
    ↓ MarkdownLoader / HTMLLoader / PDFLoader
    ↓ RecursiveCharSplitter (chunk_size=500, overlap=50)
    ↓ BGE-M3 embed_documents
    ↓ ChromaStore.add
    ↓ BM25Indexer.build (rank_bm25)
    ↓ persist to data/chroma/ + data/bm25/
```

### 3.2 在线查询流程

```
User query
    ↓ (可选) Query Rewrite / HyDE
    ↓ Hybrid Retrieve (BM25 + Vector, top_k=50)
    ↓ BGE Rerank (top_n=5)
    ↓ Prompt Assembly (context + query)
    ↓ Qwen-Long Generate
    ↓ Answer + Citations
```

### 3.3 Agent 流程（Phase 4）

```
User query
    ↓ Planner: 拆解子问题
    ↓ Researcher(s): 并行检索每个子问题
    ↓ Writer: 汇总写草稿
    ↓ Critic: 评估草稿质量
    ↓ (可选) Reflect → Researcher 重做
    ↓ Final Answer
```

## 4. 关键设计决策

### 4.1 为什么选 BGE-M3？
- 中文 SOTA（MTEB 中文榜常年 Top 3）
- 多语种支持（即使混英文也能处理）
- 支持稀疏+稠密统一编码（面试可讲）

### 4.2 为什么用 Chroma 而非 Milvus？
- 本地零成本，跑通为先
- Milvus 是分布式方案，Phase 5+ 再升级

### 4.3 为什么先 Naive 再 Advanced？
- Naive RAG 是基线，没有 baseline 就没法谈"优化"
- Advanced RAG 每一步优化都需要 Recall/MRR 指标支撑

### 4.4 为什么用 LangGraph 而非裸写 Agent 循环？
- LangGraph 是网易面经 Q9 必考点
- 提供 Checkpointing / Human-in-the-Loop 原生支持
- 状态管理可观测

### 4.5 为什么引入 RAGAS？
- 没有评测就没有"提升"
- RAGAS 自动评估节省人工标注时间
- 面试可讲完整评测方法论
