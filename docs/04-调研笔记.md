## 五、技术栈选型理由

### 5.1 LLM：Qwen-Long
- ✅ 中文 SOTA
- ✅ 128K 长 context
- ✅ 价格便宜（¥0.0005/千 token）
- ✅ 支持 Function Call
- 备选：Claude 3.5（工具调用更强）、GPT-4o（综合最强）

### 5.2 Embedding：BGE-M3
- ✅ 中文 MTEB 榜 Top 3
- ✅ 多语种支持
- ✅ 1024 维平衡性能与存储
- 备选：text-embedding-3-large（3072 维、更贵）

### 5.3 Reranker：bge-reranker-large
- ✅ 中文开源 SOTA
- ✅ Cross-Encoder 精度高
- 备选：Cohere Rerank（API 收费）

### 5.4 Vector Store：Chroma
- ✅ 本地零成本
- ✅ 与 LangChain 集成度高
- 升级路径：Milvus（分布式）、Qdrant（性能强）

### 5.5 框架：LangChain + LangGraph
- ✅ 面试核心考点
- ✅ 生态最完整
- ✅ Checkpointing / Human-in-the-Loop 原生

### 5.6 评测：RAGAS
- ✅ 业界标准
- ✅ Faithfulness / Context Recall / Answer Relevance 三件套
- 备选：DeepEval、Braintrust

## 七、Anti-pattern（不要踩的坑）

1. ❌ **不要用纯向量召回** — BM25 仍然是精确匹配必备
2. ❌ **不要跳过评测** — 没有指标的优化就是盲调
3. ❌ **不要写大而全的工具** — 小工具多组合更可控
4. ❌ **不要忽视 LangSmith trace** — 没 trace 没法 debug
5. ❌ **不要用 OpenAI 默认** — 中文场景优先 Qwen
6. ❌ **不要假设 LLM 输出稳定** — 加 JSON Schema 校验

## 八、面试叙事模板

> **项目 A（深度研究智能体）— GameGuide AI 多 Agent 版**
>
> **S**：想复现 ChatGPT Deep Research，验证多 Agent 在游戏攻略类复杂查询的可行性
>
> **T**：设计 LangGraph 多 Agent 系统，从 query 拆解到最终报告
>
> **A**：
> - 用 LangGraph StateGraph + Supervisor 模式
> - Planner → Researcher (并行) → Writer → Critic → Reflection
> - 接入 SQLite Checkpointer 支持中断恢复
> - RAGAS 评测，Faithfulness 0.92
> - 复现 Anthropic Contextual Retrieval 49% 失败率下降
>
> **R**：
> - 复杂查询（10+ 子问题）从 3 分钟 → 1 分钟
> - 端到端 Faithfulness 0.92 / Answer Relevance 0.88
